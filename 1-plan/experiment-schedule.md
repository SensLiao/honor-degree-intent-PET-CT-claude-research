## 一、目标和判定

- 判定线：K 系列每个模型两次 VAL（网络单独、网络加翻转）有一次第五轮 Dice 到 0.79 就报告导演（D-2026-10-06-03）。最终目标仍是测试集（TEST）第五轮 Dice 超过 0.80，并超过已完成的全部基线。
- K4 是新模型。D-2026-10-06-03 授权的是 K1 到 K3 的 TEST，K4 过线后先报告，由导演单独定测不测。
- 最终模型只用从零训满 40k 的版本，续训结果只当历史（导演 10-05 晚）。

不训练、很便宜的补充诊断（Codex 第三轮建议，K4 训练期间可在 5090 做，不占 z390）：

- D2 补测删笔：复用 20 个删笔单元，固定原来挑中的那批体素，把难负样本拆成 O、P 两部分（保持原来的共同分母，不能各自求平均再相加），再算 K4 那种“只从 P 重新挑满名额”的梯度，看 K4 在删笔上相对原定版本多了什么作用；同时补测 O 区域平均 pO、pP 的变化，回答“O 上的概率被推给了谁”。单模型、不训练，约 20 分钟。
- 精确排序：在服务器上用原始分数逐扫描算 AUC，按距离分层再按病人平均，代替 40 档分箱的估计。

## 五、过线以后的归因（导演定的顺序：先出效果，再拆）

- 最省的拆法是 2×2 析因（把两个因素的有无交叉成四种组合）：v1 和 K1 已经是两个角，再训“K1 去掉难负样本”和“v1 加上难负样本”两次，约 40 GPU 小时，就能分出难负样本自己的作用、其余部件的作用和两者的交互（文献报告 A1）。K4 是“只在加笔上去掉”的版本，可以作为第五种组合并排报。
- 一次换种子重训，量清楚同一配方能晃多少（R0 当时被停掉让路，一直没量），否则 ±0.01 以内的差都不能解读。
- 逐个部件去掉要 6 次 40k，而且看不到交互，不推荐；部分析因 8 次起步，主效应和两两交互仍分不开。
- 下一次训练起，训练日志加三样记录：按笔方向的“推高 T / 压低 T”梯度比，T 的平均 pT 和被选难负体素平均 pT 之差，固定一批训练单元上的 T 平均分数。成本几乎为零，以后就不用事后猜分歧从哪一步开始。

## 六、保证公平干净的对比

| 项 | 规则 |
|---|---|
| 同起点 | 候选和对照都从随机初始化训满 40k，不从任何 checkpoint 起步 |
| 同预算 | 40k 优化步；回放、重算、拟合另记 GPU 小时 |
| 同数据 | 同划分、同离线库、同一个固定教师状态池；K2 另加自己刷新出的状态，写明 |
| 同种子 | 一组比较里种子相同（3407）；3408 只用来看波动和做集成 |
| 同画法分配表 | 快速 VAL 一律用 `val-style-roster.json`；三画法 VAL 三种全跑 |
| 同执行器 | 每个网络同时报 0.5 和组 A 两种读数；基线按作者自己的执行设置 |
| 同评测 | 冻结机器人（原 simulate_scribble 和 choose_correction）、3 mm 网格、5 轮、原生 Dice、18 邻接、冻结评测器；同一扫描先对画法平均，再在患者内对扫描平均，最后患者等权 |
| 机器 | 训练可在不同机器、不同 PyTorch 版本，回执写明；同一张比较表的 VAL 评估尽量在同一台机器；省显存开关只改显存不改结果，照样记 |

每个运行的身份至少记：数据和标签版本、患者划分、起点分割来源、初始化方式（随机）、配方哈希、组别和各开关、状态池哈希和刷新记录、组 A 打分器哈希、候选生成器和硬规则版本、写回和机器人版本、种子、步数、读数据进程数、机器和 PyTorch 版本、执行方式、画法分配表哈希。改了会影响输出的任何一项就是新身份。

快速 VAL 和三画法 VAL 不混比：差值只在同一类型、同一分配表里算（快速 VAL 的 v1 参照 0.7562，三画法的 v1 参照 0.7524）。54 位患者，快速 VAL 第五轮 Dice 的配对差区间约 ±0.02，1 到 2 个点以内的差单看一次分不出真假。反复在同一批 VAL 上挑，赢家会偏乐观；v1 的 VAL→TEST 落差（flat +1.70 点、N3 +2.53 点）只是两次观察，不当换算公式。TEST 每个模型只用一次，开发期间不用 TEST 选模型、选参数。
