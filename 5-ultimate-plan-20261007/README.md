结论：这个文件夹给出一套“三段式指代程序”的下一版网络与训练方案（先绑定这一笔指哪块错，再定修到哪里为止，最后按符号写回），一份分阶段、分机器的实验表，一组每条主张都带判伪臂的对照设计，以及七个领域共 700 篇以上本次运行逐篇打开来源页核实过的文献登记。所有数字都标明训练集 / 验证集 / 测试集和出处；所有预期收益都写成“有证据支持的假设”并标证据等级，没有任何一个是跑出来的。测试集在开发期零接触。

## 阅读顺序（给负责人）

1. `STATUS.md`：进度、七个领域各核实了多少篇、还差什么、更新时间。
2. `ULTIMATE-PLAN.md`：究极 plan。第九节是要你定的事（A/B/C 加推荐），第十节是你现在要做什么。
3. `02-core-idea-and-novelty.md`：依据什么原理、用什么方法、解决什么问题、预期什么结果、对什么领域有价值、还有哪些要提升。
4. `01-review-of-current-results.md`：为什么卡在 0.75，按证据强弱排序的原因清单，定量推理，现有结论里站不住的地方，对下一版的硬约束。
5. `06-risks-and-falsification.md`：最可能失败的环节、触发读数、退路，判伪条件总表。
6. `07-adversarial-review-log.md`：两轮“苛刻审稿人 + 实验失败预测者”的意见和据此做的修订。
7. `03-module-by-module-candidates-part1.md`、`-part2.md`：逐模块的候选改法（输入、笔的编码、绑定、范围、解码、门槛、增强、远端；损失、标定、训练状态、抽样、配对、历史、预算、增强与画法）。
8. `05-experiment-configs-proposal.md`：每个候选的配置字段含义与取值范围（给工程师）。
9. `04-cross-domain/`：七个领域各一份综述 `review-<领域>.md`，各一份登记表 `literature-register-<领域>.csv/.json`（已核实），`literature-unverified-<领域>.json`（未核实，不计数），`count_verified.py`（统计脚本），`registers/` 是子主题原始登记。
10. `work/`：给子 agent 的项目简报与规则、子主题分配、已有调研摘要、直接近邻新意核查、SOTA 与协议背景。

## 文件之间的关系

`01` 说明病在哪 → `02` 说明怎么治和为什么 → `03` 列出每个部位的全部备选 → `ULTIMATE-PLAN` 挑出强组合、排进机器和日历、配上判伪臂 → `05` 把每个实验写成配置字段 → `06`、`07` 反过来挑毛病并改回前面的文件 → `04-cross-domain` 是前面所有“原理依据”的来源登记。

## 本文件夹遵守的规矩

- 测试集零接触；选模型、选参数只用训练集和验证集；数字必须写明集合；上限和 oracle 标“上限”。
- 最终模型从随机初始化干净训满 40k；比较锁同划分、起点、预算、种子、画法分配表。
- 系数、门槛、步数、配额要么学出，要么按每例数据和模型自估量的通用规则推出；算力预算登记进配置；评测协议不动。
- 一个实验一个配置文件，新实验只加配置不改代码；实验名“部分-对象-动作”自描述。
- 只写文档和计划，不改项目源码；文献只有本次打开来源页核实过的才进登记表和正文。
