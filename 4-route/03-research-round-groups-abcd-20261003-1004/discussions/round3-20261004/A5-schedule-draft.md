# SIRB-Net 第二版实验计划安排（草稿，并行 agent A5，2026-10-04 凌晨）

**结论**：十月里 SIRB 能靠得住的显卡只有 z390 的一张 3090。主实验按“执行端选择器 → 续训强组合 → 结构增强”三组串行，第一轮约 10-10 出齐，之后两段改进；10-22 起不再加新部件。只靠 z390，最佳系统最晚 10-25 定下；A6000 按 UAM 正常速度在 10-14 前空出、并且第二种子在主实验期间已训好时，可推到 10-27。定下当天申请最终模型的一次性 TEST 授权（跑 8 到 16 小时，估），随后约 3 到 4.3 天（估，含四分之一机动）跑完最小消融清单，10-30 收尾，10-31 只留给失败重跑和回传。

两处旧估计要改，排日程时已按新数：

- TRAIN 回放按约 6 小时排，不按 2 到 3 小时。10-03 两次 TRAIN 回放实测 5.87 和 5.92 小时（`records/editor-sirb-v2-batches/registry.tsv`）。内存整理卡顿修好以后，训练从 5.7 到 6.5 秒/步降到约 1.25 秒/步，评估却没变快：快速 VAL 修复前 1.42 小时（N1_STATE_STATIC），修复后 1.53 小时（N1_STATE_INDUCED）。评估类任务的单位成本是每次整卷推理约 10 到 11.5 秒，回放、快速 VAL、三画法 VAL、TEST 的时长都按推理次数乘它来估。
- 主实验阶段卡的是写码和等结果，显卡时数够用：10-04 中午到 10-25 中午约 500 个 GPU 小时，主实验估用 220 到 300 小时。消融阶段反过来，显卡成了瓶颈。所以主实验期间显卡一有空档，就先补“当前最好配方的第二种子”：它是集成成员，如果这个配方最后入选，它就是论文要的第二种子。

记号沿用计划目录 PLAN.md：T、O、P、pT、D5、nAUC（起点加五轮六个状态的 Dice 曲线下面积）、快速 VAL（99 个扫描每例一种画法）、三画法 VAL（每例三种画法）。“起点模型”指 10-04 中午三个续训候选里快速 VAL 最好的那个：N1_STATE_STATIC 0.7602、N1_STATE_INDUCED 0.7606（两者差 0.0004，在噪声内，按 nAUC 0.7234 对 0.7189 取 N1_STATE_INDUCED），N1_STATE_SPATIAL 约 10-04 中午出数后一起比。所有日期都假定导演 10-04 白天听完讲解说开始；每晚一天，主实验少一天，10-25 的定下日不动。

## 四、保证公平干净的对比

| 项 | 规则 |
|---|---|
| 同父 | 比较的两个模型从同一个父 checkpoint 出发，记哈希。强组合和它的消融都从 v1 flat 40k 起；结构增强从强组合赢家起 |
| 同步数 | 8k 只算优化步数；回放、重算、拟合另记 GPU 小时。结构增强比强组合多 8k，二者相比只能说“系统更强”，模块贡献看同预算对照 |
| 同状态池 | 池按回放名和哈希登记；消融复用最终模型训练时记录下的池 |
| 同种子 | 一组比较里种子相同（主线 3407）；第二种子只用来看最终系统的方差 |
| 同画法分配表 | 快速 VAL 一律用 `val-style-roster.json`；三画法 VAL 三种画法全跑 |
| 同执行器 | 网络之间比较用同一种执行方式；选择器每个 checkpoint 各自重拟合，算系统的一部分；同一 checkpoint 的 0.5 和选择器并排报；基线按作者自己的执行设置 |
| 同评测 | 冻结机器人（原 simulate_scribble 和 choose_correction）、3 mm 网格、5 轮、原生 Dice、18 邻接、冻结评测器；同一扫描先对画法平均，再在患者内对扫描平均，最后患者等权 |
| 同机器 | 同一组比较的 VAL 评估在同一台机器上跑（默认 z390）；跨机训练写机器和 PyTorch 版本 |

续训对照的用法：N1_STATE_STATIC（v1 flat 加原配方 8k，快速 VAL D5 0.7602；同一分配表下 v1 是 0.7562）是“多训 8k”的参照。任何从 v1 flat 起的 8k 候选先和它比，超出的部分才算配方的贡献。结构增强的同预算参照是“强组合赢家按原配方再续 8k”，只在最终含结构增强时于消融阶段跑。选择器的参照是同一 checkpoint 的 0.5 执行，不另训。

每个运行的身份至少记：数据和标签版本、患者划分、起点分割来源、父 checkpoint 哈希、编辑网络代码和配方哈希、选择器与候选生成器版本、网格与写回版本、机器人版本、所用回放池的名字和哈希、种子、训练步数和刷新点、读数据进程数、机器、GPU 和 PyTorch 版本、执行方式（0.5、选择器、翻转平均、集成）、画法分配表哈希。改了其中会影响输出的任何一项，就是新身份。

快速 VAL 和三画法 VAL 不混比：差值只在同一类型、同一分配表里算（快速 VAL 的 v1 参照是 0.7562，三画法的 v1 参照是 0.7524）。VAL 上的差值都给按患者重抽样（bootstrap，成对重抽患者估区间，10,000 次，种子 3407）的区间。噪声有多大可以看一个现成例子：原配方多训 8k，快速 VAL D5 差 +0.0041，区间是 [−0.0152, +0.0208]（VAL，54 位患者）。所以快速 VAL 上 1 到 2 个点以内的差，单看一次分不出真假。

TEST 每个模型只用一次，导演另行授权；开发期间不用 TEST 选模型、选参数，也不看 TEST 决定加不加某个部件。v1 的 VAL→TEST 落差（flat +1.70 点、N3 +2.53 点）只是两次观察，不当换算公式。

## 五、找最佳组合

先跑的三组，每组都当一个整体比较，不做全因子组合：

| 时点 | 看什么 | 怎么走 |
|---|---|---|
| 执行端选择器出结果（约 10-06） | 同一 checkpoint 选择器对 0.5 的快速 VAL D5 和 nAUC；留出 TRAIN 患者上被选候选的真实收益和 O、P 改动；不改的比例和同一目标反复出现的次数 | 好于 0.5：后面每个新 checkpoint 都配重拟合的选择器；不好：后面只用 0.5，选择器留作论文分析 |
| 续训强组合出结果（约 10-07 夜到 10-08） | 强组合对起点模型和 N1_STATE_STATIC（同执行方式）；分痛点读数 | 最好：作结构增强的父模型。不如起点模型：按读数挑最可疑的一组，做一次“强组合去掉这一组”（约半天），这是为下一轮改进服务的归因，不算消融 |
| 结构增强出结果（约 10-10） | 结构增强对强组合（同执行方式） | 更好就留；不好最终用强组合，结构增强写进论文分析 |
| 第二、三段（10-11 到 10-20） | 每个候选对当时最好 | 方向按第一轮分痛点读数定：哪处丢分最多、哪组改动在那处读数上动了，就加强哪组 |

三画法 VAL 什么时候补：候选在快速 VAL 上成为新最好（D5 点估计最高，nAUC 不低于当时最好）就补，每段最多一两次，约 6 到 9 小时一次。三画法 VAL 的 D5 到 0.79 立即报导演一次，内容是当前模型、D5 和 nAUC、同分配表增量、已完成和未完成的项；到 0.80 再报。

晋级看五轮结果：快速 VAL 的 D5 为主，nAUC 不能明显变差；T 修回、O 改动、P 新错、不改比例、重复目标只用来解释收益从哪来，不单独否决一个 D5 更高的候选。单步理想上限、打分头误差小、候选平均相关高，都不算晋级证据。

停止加新部件的条件，满足一条就停：三画法 VAL 到 0.80 且导演满意；连续两个候选都没成为新最好；到 10-22 24:00。
