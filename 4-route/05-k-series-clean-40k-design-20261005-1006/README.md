# 第 05 阶段：K 系列从零训满 40k 的设计和开训（10-05 晚到 10-06）

## 为什么做

导演 10-05 晚指出：续训的部件只在训好的网络上学 8k 步，不代表从零训的效果；最终模型也会变成“nnU-Net 基座加 40k 加 8k”三段训练，论文说不干净。所以候选、最终模型和归因一律从随机初始化训满 40k，先并行训几个完整组合比结果（`D-2026-10-05-01`）。

## 做了什么

第一批三个完整组合，同划分、同起点、flat 输出头、v1 的主干、优化器和日程，种子 3407：

- K1：v1 配方加组 B 六个部件一次合训（B1 编辑合同、B2 远处距离不截断和远端训练块、B3 上一轮实际改动作输入、B4 固定教师状态池、B5 块内配对、B6 第 1000 步标定）。
- K2：K1 加第 10k、25k 步两次在线刷新，用当时的模型在一半 TRAIN 病人上走五轮，新状态并入池。
- K3：K1 加宽状态主干 1.5 倍，作候补。

Codex 第 11 轮审了方案，采纳四处：组 C 本月不写、K3 降为候补、B6 改到第 1000 步只标定软 Dice 收益项、K2 在 10k 和 25k 刷新。10-05 21:00 导演批了删除清单、5090 排上、哈希只核文件是否一致、代码按模型分文件夹（`D-2026-10-05-02`）；23:20 定开训 K1、K2、K3（`D-2026-10-05-03`）。代码分两批由子 agent 写，Codex 只读审出四处问题，修好后部署。10-06 01:44 到 01:55 三台开训：K1 在 z390，K3 在 A6000 GPU0，K2 在 5090。量换种子波动的 R0 给 K1 让路，10-06 00:14 停掉删了，这项波动一直没量。

10-06 傍晚排好每个 K 训完后的评估。18:4x 导演定 K 系列不用组 A，最终系统是网络加翻转（`D-2026-10-06-01`）；20:45 和 22:05 定下 TEST 规矩（`D-2026-10-06-02`、`D-2026-10-06-03`）：每个 K 的两次 VAL 只要有一次到 0.79，就在它自己训练的机器上，网络单独和网络加翻转各测一次 TEST，测完这台机器再接 baseline。

## 结果

这一阶段只定配方、开训，不出成绩。K1 到 K3 的成绩在第 06 阶段。

## 发现

当时写下的最大风险是：三个组合共用一套组 B 配方，只要有一件起反作用，K1、K2、K3 会一起变差。第 06 阶段证实了这一条。

`D-2026-10-05-01`、`D-2026-10-05-02`、`D-2026-10-05-03`、`D-2026-10-06-01`、`D-2026-10-06-02`、`D-2026-10-06-03`，全文在 vault 的决策正本。
